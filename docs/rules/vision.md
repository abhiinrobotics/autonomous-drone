# Vision rules

- Everything in `vision/` is a pure function: `(frame, params) -> result dataclass` with `confidence`. No camera, no MAVLink, no globals (create CLAHE/detectors once in a small class built from params).
- Image convention: u right, v down, origin top-left. **Error sign conventions are defined once** (docstring + test): `err_u_px = u_target - u_center` positive = target right of centre. Mapping to body axes happens in `core/camera_model.py` using the configured camera mount rotation (down cam: image-up = body-forward by default, configurable). Never flip signs inside phases.
- Camera config (hardware.py): resolution, HFOV/VFOV or intrinsics, mount rotation, exposure/focus mode. SITL gets FOV from the SDF; hardware from calibration later. Pixel->metre via altitude and intrinsics; never use fixed px-to-velocity gains for the down cam.
- Pair each frame with the attitude/position at capture time (`Camera.read()` returns frame + monotonic timestamp; look up the nearest state sample). Tilt-compensate the projection.
- QR: `pyzbar` on enhanced grayscale (CLAHE + mild sharpen), multi-QR per frame, return data + polygon + side length px. Physical QR size is config (`qr_size_m`, default 1.0) -> used for range sanity checks. Confirm a target by N consistent detections (config), not one.
- Banner (green): HSV mask on CLAHE-normalised V, then **shape gating** (min area, aspect ratio, solidity) and an ROI above the horizon so grass is rejected. Return centroid, bbox, apparent width (for range).
- Corridor: do NOT classify walls by slope sign (each wall shows two edges with opposite slopes). Use Hough segments, group by position relative to the vanishing/centre column, intersect with a fixed image row (e.g. 80 % height) to get left/right wall x, centre = midpoint; single-wall fallback uses the known corridor width and apparent scale; return lateral error, heading error, confidence. Low confidence -> controller holds last good command briefly then slows.
- Obstacles (return lane): dark/black blocks inside the lane ROI; return bearing, lateral extent, rough range from apparent size and the front range sensor. Combine with front range: camera gives direction, range sensor gives distance.
- Red zone: red hue wraps (0-10 and 170-180); output polygons in pixels -> project to ground -> merge into runtime no-fly set with buffer.
- Performance budget: <= 100 ms/frame on a Pi 4B for the per-tick path. Benchmark in tests (`tests/vision/test_perf.py`, soft threshold); downscale ROIs, avoid per-frame allocations, run QR decode at reduced rate if needed.
- Tests use frames captured from the sim (`tests/data/`, small, committed via script-generated manifest) plus augmentations (blur, noise, gamma, brightness drift). Every detector has: positive, negative, and sign-convention tests.
